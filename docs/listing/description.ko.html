폴더 필터 스케줄러는 메시지 필터 규칙을 모든 폴더에서 일정에 따라 자동으로 실행합니다. Thunderbird는 받은 편지함에서만 필터를 자동으로 실행합니다. 그래서 메일 서비스 제공업체가 서버에서 스팸이나 대량 메일 폴더로 분류한 메일, 또는 다른 폴더에 있는 메일은 필터가 적용되지 않습니다. 이 부가 기능은 그 빈틈을 메웁니다. 주요 기능
  • 받은 편지함뿐 아니라 원하는 모든 폴더에서 규칙 실행
  • 타이머, 새 메일 도착, 규칙 자체의 Cron 일정, 또는 클릭 한 번으로 즉시 실행
  • 규칙 하나로 여러 계정에 걸쳐 동작
  • 나중에 만드는 폴더를 포함해 폴더의 모든 하위 폴더 포함 가능
  • 이미 받은 스팸에서 오른쪽 클릭 한 번으로 보낸 사람 도메인 차단 목록 작성
  • SPF, DKIM, DMARC 확인 및 DKIM 서명 직접 검증
스팸 도메인 차단 메시지 목록 어디서든 스팸을 선택하고 오른쪽 클릭한 다음, 폴더 필터 스케줄러, 스팸 도메인 추가를 차례로 선택합니다. 보낸 사람 도메인은 Reply-To와 From 양쪽에서 읽어 검토할 수 있도록 그룹을 나누어 보여 주고, 일반 일정에 따라 일치하는 메일을 휴지통으로 옮기는 규칙에 추가합니다. 하위 도메인도 자동으로 포함되므로 evil.com을 차단하면 bounce.evil.com도 걸러집니다. Gmail, Yahoo, Outlook, iCloud 같은 잘 알려진 메일 서비스는 차단하지 않으며, 이 보호 목록은 직접 편집할 수 있습니다. SPF, DKIM, DMARC 확인 SPF, DKIM, DMARC 통과 여부로 메일을 일치시켜 "DMARC에 실패한 메일을 스팸으로 이동" 같은 규칙을 만들 수 있습니다. 부가 기능은 메일 서비스 제공업체가 추가하는 Authentication-Results 헤더를 읽습니다. 보낸 사람이 이 헤더를 위조할 수 있으므로, 부가 기능은 DKIM 서명도 직접 검증하고 두 결과로 DMARC를 판단합니다. 각 메시지는 한 번만 확인하며, 결과는 최대 90일 동안 보관합니다. 고급 아래의 설정에서 DNS 서버, 두 결과가 다를 때 우선할 결과, 헤더를 신뢰할 서버를 고릅니다. DKIM 코드는 Philippe Lieser의 DKIM Verifier에서 가져왔습니다. 조건 보낸 사람, 받는 사람, 참조, 제목, Reply-To, List-Id, Sender를 포함, 일치, 시작 문자열, 끝 문자열, 정규식 일치로 비교합니다. 경과 기간이 N일 초과 또는 미만인지로 일치시켜 "30일 지난 알림을 보관함으로 이동" 같은 규칙을 만들 수 있습니다. 보낸 사람이나 받는 사람, 참조의 수신자가 주소록 중 하나에 있는지, 또는 어느 주소록에도 없는지 확인합니다. 보낸 사람 이름에 실제 주소와 다른 도메인의 주소를 보여 주는 흔한 스팸 수법도 잡아냅니다. 메시지가 읽음인지, 별표가 있는지, 스팸으로 표시되었는지, 내 태그 중 하나가 있는지, 우선 순위가 무엇인지, SPF, DKIM, DMARC를 통과하는지 확인합니다. 각 조건은 부정할 수 있고 AND 또는 OR로 조합할 수 있습니다. 조건 하나에 도메인 목록 전체를 담을 수도 있으며, 오른쪽 클릭 동작이 채우는 것이 바로 이 목록입니다. 동작
  • 휴지통으로 이동 (각 메시지의 계정으로)
  • 보관 (Thunderbird의 보관 단추처럼 각 계정의 보관 설정 사용)
  • 다른 계정의 폴더를 포함해 원하는 폴더로 이동 또는 복사
  • Thunderbird 태그 지정 (메시지에 이미 있는 태그는 유지)
  • 읽음 또는 읽지 않음으로 표시, 별표 추가 또는 제거, 스팸 또는 스팸 아님으로 표시
  • 영구 삭제
규칙 하나에 여러 동작을 넣을 수 있으므로 "친구 태그를 지정하고 친구 폴더로 이동"이 규칙 하나가 됩니다. 어떤 순서로 넣든 이동하거나 삭제하는 동작이 마지막에 실행되므로, 다른 동작도 메시지를 그대로 처리할 수 있습니다. 백업과 프로필 간 이동 규칙을 JSON 파일로 내보내고 다시 가져올 수 있습니다. 이미 있는 규칙은 인식해서 중복으로 만들지 않고 건너뛰므로, 공유받은 파일을 가져와도 안전합니다. 규칙이 실행되는 시점 규칙은 설정한 타이머에 따라 실행되고, 감시 중인 폴더에 새 메일이 도착하면 몇 초 안에도 실행됩니다. 도착한 메일은 묶어서 처리하므로 메일 동기화 한 번에 실행도 한 번이며, 메일을 받은 폴더를 감시하는 규칙만 확인합니다. 규칙마다 자체 일정을 둘 수도 있으며, 매일 21:00을 뜻하는 0 21 * * * 같은 Cron 표현식으로 씁니다. 그러면 그 규칙은 그 시각에만 실행되고, Thunderbird가 닫혀 있어 놓친 실행은 다음 시작 때 실행됩니다. 규칙을 직접 실행하려면 도구 모음 단추, 오른쪽 클릭 메뉴, 또는 규칙의 실행 단추를 사용합니다. 옵션 페이지의 고급 섹션에서 새 메일 트리거를 끄고 검사 시간을 조정할 수 있습니다. 속도와 Reply-To 보낸 사람, 받는 사람, 참조, 제목 조건은 색인된 데이터를 사용하므로 아무것도 내려받지 않습니다. Reply-To 같은 색인되지 않은 헤더의 조건은 메시지 자체가 필요하며, 온라인 IMAP 폴더에서는 필요할 때 메시지를 가져옵니다. 속도와 오프라인 사용을 위해 해당 폴더의 오프라인 저장소를 켜세요. 예약 실행은 이전 실행 이후 도착한 메일만 보고, Date 헤더가 실제 도착보다 늦은 메일을 위해 30분마다 더 넓은 보충 검사를 합니다. 그래서 큰 폴더도 부담이 적습니다. "지금 모든 규칙 실행"은 항상 모든 메일을 검사합니다. 개인정보 데이터를 수집하거나 판매하지 않으며, 분석이나 원격 측정 기능이 없습니다. 규칙은 Thunderbird 안에서 로컬로 실행되며, 메시지 내용은 기기 밖으로 나가지 않습니다. 사용자의 메일 서버 외에 부가 기능이 연결하는 서버는 선택 사항인 DKIM 확인용 DNS 서버뿐이며, 이 확인은 SPF, DKIM, DMARC 조건이 있는 규칙에서만 실행됩니다. selector._domainkey.example.com이나 _dmarc.example.com 같은 도메인 이름의 DNS 조회를 사용자가 고른 Cloudflare 또는 Google에 보내며, 사용자가 허용한 뒤에만 보냅니다. 주소록과 태그 목록 접근은 선택 사항이며, 이를 필요로 하는 조건이나 동작을 사용할 때만 요청합니다. 진단 보고서는 사용자가 직접 공유할 때만 공유되며, 포함하도록 선택하지 않으면 주소, 도메인, 패턴, 폴더 이름을 숨깁니다. 오픈 소스 MPL-2.0 라이선스로 배포합니다. 소스, 이슈, 기여는 github.com/KayhanB21/folder-filter-scheduler에서 환영합니다.
