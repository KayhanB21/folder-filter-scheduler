フォルダーフィルタースケジューラーは、メッセージフィルターのルールを任意のフォルダーで、スケジュールに従って自動的に実行します。Thunderbird がフィルターを自動実行するのは受信トレイだけです。そのため、プロバイダーがサーバー側で迷惑メールフォルダーや一括送信フォルダーに振り分けたメールや、他のフォルダーにあるメールにはフィルターが適用されません。このアドオンはその穴を埋めます。 主な機能
  • 受信トレイだけでなく、選択した任意のフォルダーでルールを実行
  • タイマー、新着メールの受信時、ルール独自の cron スケジュール、またはワンクリックですぐに実行
  • 1 つのルールで複数のアカウントを対象にできる
  • フォルダーのすべてのサブフォルダーを対象にでき、後から作成したサブフォルダーも含む
  • 手元にある迷惑メールから、右クリック 1 回で送信者ドメインのブロックリストを作成
  • SPF、DKIM、DMARC を確認し、DKIM 署名を自ら検証
迷惑メールのドメインをブロックする メッセージ一覧の任意の場所で迷惑メールを選択して右クリックし、[フォルダーフィルタースケジューラー]、[迷惑メールのドメインを追加] の順に選択します。送信者ドメインは Reply-To と From の両方から読み取られ、確認用にグループに分けて表示されます。追加したドメインは、一致したメールを通常のスケジュールでごみ箱へ移動するルールに加えられます。サブドメインも自動的に対象になるため、evil.com をブロックすると bounce.evil.com もブロックされます。Gmail、Yahoo、Outlook、iCloud などのよく知られたプロバイダーはブロックされません。この保護リストは自由に編集できます。 SPF、DKIM、DMARC の確認 SPF、DKIM、DMARC の確認に成功したか失敗したかでメールを判定できます。たとえば「DMARC に失敗したメールを迷惑メールフォルダーへ移動する」といったルールを作成できます。アドオンは、プロバイダーが追加する Authentication-Results ヘッダーを読み取ります。このヘッダーは送信者が偽装できるため、アドオンは DKIM 署名を自ら検証し、両方の結果から DMARC を判定します。各メッセージの確認は 1 回だけ行われ、結果は最長 90 日間保存されます。[詳細設定] では、使用する DNS サーバー、2 つの結果が一致しないときにどちらを優先するか、どのサーバーのヘッダーを信頼するかを設定できます。DKIM のコードは Philippe Lieser 氏による DKIM Verifier に由来します。 条件 差出人 (From)、宛先 (To)、Cc、件名 (Subject)、Reply-To、List-Id、Sender で判定でき、「に次を含む」「が次と一致する」「が次で始まる」「が次で終わる」「が次の正規表現にマッチする」を使えます。メッセージの経過日数が N 日を超えるか、N 日未満かでも判定できます。たとえば「通知メールを 30 日後にアーカイブへ移動する」といったルールを作成できます。送信者、または To や Cc の受信者のいずれかが、アドレス帳のいずれかに含まれるか、どのアドレス帳にも含まれないかを確認できます。送信者名に実際のアドレスとは別のドメインのアドレスが表示されている場合も検出できます。これは迷惑メールによくある手口です。メッセージが既読か、スター付きか、迷惑マークが付いているか、自分のタグが付いているか、重要度は何か、SPF、DKIM、DMARC の確認に成功しているかも確認できます。各条件は否定でき、AND または OR で組み合わせられます。1 つの条件にドメインの一覧をまとめて登録することもでき、右クリックの操作ではこの一覧に追加されます。 アクション
  • ごみ箱へ移動 (各メッセージのアカウントのごみ箱へ)
  • アーカイブ (各アカウントのアーカイブ設定を使用。Thunderbird の [アーカイブ] ボタンと同じ動作)
  • 任意のフォルダーへ移動またはコピー (別のアカウントのフォルダーも可)
  • Thunderbird のタグを付ける (メッセージに付いている既存のタグはそのまま)
  • 既読または未読にする、スターを付けるまたは外す、迷惑マークを付けるまたは外す
  • 完全に削除
1 つのルールに複数のアクションを設定できるため、「友人のタグを付けて友人フォルダーへ移動する」も 1 つのルールで行えます。どの順番で並べても、移動または削除するアクションは最後に実行されるため、他のアクションもそのメッセージを処理できます。 バックアップとプロファイル間の移行 ルールは JSON ファイルにエクスポートし、インポートで戻せます。既にあるルールは認識されて重複せずにスキップされるため、共有されたファイルも安全にインポートできます。 ルールの実行タイミング ルールは設定したタイマーで実行されるほか、監視しているフォルダーに新着メールが届くと数秒以内に実行されます。届いたメールはまとめて処理されるため、1 回のメール同期で実行は 1 回だけです。また、メールを受信したフォルダーを監視しているルールだけが確認されます。ルールには独自のスケジュールを cron 式で設定することもできます。たとえば 0 21 * * * は毎日 21:00 を表します。その場合、ルールは指定した時刻にだけ実行され、Thunderbird を閉じていたために実行されなかった分は次回の起動時に実行されます。ルールを手動で実行するには、ツールバーボタン、右クリックメニュー、またはルールの [実行] ボタンを使います。オプションページの [詳細設定] セクションでは、新着メールによる実行をオフにしたり、スキャンのタイミングを調整したりできます。 速度と Reply-To について 差出人、宛先、Cc、件名の条件はインデックス化されたデータを使うため、何もダウンロードしません。Reply-To など、インデックス化されていないヘッダーの条件にはメッセージ本体が必要で、オンラインの IMAP フォルダーでは必要に応じて取得されます。速度とオフラインでの利用のために、そのフォルダーのオフライン保存を有効にしてください。スケジュール実行では前回の実行以降に届いたメールだけを確認します。加えて、Date ヘッダーの日付が実際の到着より遅れているメールのために、30 分ごとに範囲を広げた補完スキャンを行います。そのため、大きなフォルダーでも負荷は小さく抑えられます。[すべてのルールを今すぐ実行] は常にすべてをスキャンします。 プライバシー データの収集や販売は一切行わず、アナリティクスやテレメトリーもありません。ルールは Thunderbird 内でローカルに実行され、メッセージの内容がデバイスの外に出ることはありません。アドオンが接続するサーバーは、あなたのメールサーバーを除けば、オプションの DKIM 検証に使う DNS サーバーだけです。この検証は、SPF、DKIM、DMARC の条件があるルールでのみ実行されます。selector._domainkey.example.com や _dmarc.example.com などのドメイン名の DNS 問い合わせを、あなたが選んだ Cloudflare または Google に送信します。送信は、あなたが許可した後に限られます。アドレス帳とタグ一覧へのアクセスは任意で、それらを必要とする条件やアクションを使うときにだけ許可を求めます。診断レポートはあなた自身が共有する場合にのみ共有されます。含めることを選ばない限り、アドレス、ドメイン、パターン、フォルダー名は伏せられます。 オープンソース MPL-2.0 ライセンスで公開しています。ソースコード、問題の報告、コントリビューションは github.com/KayhanB21/folder-filter-scheduler で受け付けています。
